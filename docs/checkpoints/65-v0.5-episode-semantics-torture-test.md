# v0.5 Episode Semantics Torture Test

**Date:** 2026-08-30

**Scope:** Breakpoint 2 on GPT-5.6 Sol/high

## Result

Breakpoint 2 passes after two Phase 2 corrections. Episode membership now has
a hard accumulated ceiling of 100 events, and offering an event with existing
primary membership returns a typed conflict instead of leaking a generic
SQLite uniqueness error. Decision D077 records the ambiguity policy.

No failure normalizer or experience work began during this review.

## Scenario Results

| Scenario | Proven behavior |
|---|---|
| two unrelated failures close together | Explicit membership keeps them in distinct task-scoped episodes; time proximity has no grouping effect. |
| one failure across several attempts | One caller-ordered episode retains the full failure/change/failure/change/verification sequence by ordinal. No attempt or outcome interpretation occurs yet. |
| task switch during debugging | The switched-task event fails exact null-safe task provenance and remains unassociated. |
| session ends before episode closure | Session termination does not synthesize a lifecycle transition. The caller can still close the open episode using its expected version. |
| event added concurrently with closure | Exactly one optimistic mutation commits. If close wins, the add is visibly rejected; if add wins, the episode stays open with the committed member and close must retry. |
| one event offered to two episodes | The second offer returns `Conflict`; the original primary membership is unchanged. |
| unscoped event in a task-scoped episode | The service rejects it before persistence, and the SQLite trigger independently enforces the same rule. |
| verifier result arrives after closure | Even exact matching provenance cannot append to a terminal episode. It remains raw or belongs to a new explicit episode. |
| abandoned episode followed by a new episode | Abandonment is terminal; a replacement starts with a distinct episode identity and version zero. |
| cross-workspace otherwise-identical evidence | Workspace-scoped lookup cannot resolve the foreign event, and composite database ownership prevents cross-workspace membership. |

## Additional Adversarial Proofs

- Concurrent same-version add/add requests produce one success and one typed
  conflict, with ordinal zero present exactly once.
- A durable request key is idempotent only for identical operation, expected
  version, scope, and ordered IDs; changed content conflicts.
- Member order is insertion order even when timestamps do not distinguish the
  events.
- The 101st accumulated member is rejected inside the SQLite-owned mutation
  transaction. Its request row and version increment roll back, leaving the
  episode at 100 members.
- A terminal episode cannot reopen or gain membership through direct database
  writes.
- Prior databases still migrate with no inferred episodes or memberships.

## Boundary

Explicit membership controls all v0.5 consolidation. CortexWeave does not
repair ambiguity using timestamps, payload similarity, task guessing, or
automatic episode grouping.

The next planned model boundary is Phase 3 on GPT-5.6 Terra/high.
