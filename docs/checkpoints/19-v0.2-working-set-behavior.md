# Checkpoint 19: v0.2 Working-Set Behavior

## Result

PASS. Phase 2 working-set activation, decay, bounded retention, and pin lifecycle
are deterministic and transport-independent.

## Verified Behavior

- First activation creates a workspace/session-scoped entry.
- Repeated activation increases the score up to a configured ceiling.
- Advancing an injected clock by one half-life halves the effective score.
- Activating another valid source adds it to the working set.
- Stale unpinned entries are removed during activation or inspection.
- The session item limit evicts the lowest effective unpinned activation first.
- A pin is idempotent, survives decay, and protects its matching entry.
- Unpinning allows an already-stale entry to be removed.
- Session-global entries are visible to a task, while entries from another task
  are excluded.
- Concurrent activations merge without losing increments.
- Code, document, memory, event, task, and session sources are checked against
  the selected workspace before persistence.

## Boundary

`ContextService` owns activation and decay semantics. SQLite owns persistence
statements and optimistic compare-and-update behavior. `CortexWeaveService`
exposes the operations without MCP or CLI types; adapters remain unchanged in
this phase.
