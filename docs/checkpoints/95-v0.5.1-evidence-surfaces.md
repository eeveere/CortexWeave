# v0.5.1 Checkpoint 95: Evidence Surfaces

**Date:** 2026-09-04

**Breakpoint:** BP5 implementation slice

## Result

The shared test-evidence services are now exposed through both supported
transports. The CLI provides `evidence record`, `evidence inspect`, and
`evidence capabilities`. Recording reads one JSON bundle from a caller-supplied
path and uses the capture-specific receipt and service validation; inspection
is workspace-scoped; capability output names the qualified runner profiles and
deferred integrations.

MCP advertises and dispatches the equivalent `test_evidence_record`,
`event_evidence_inspect`, and `evidence_capabilities` tools. The adapter keeps
workspace resolution and JSON transport concerns at the boundary and delegates
recording, decoding, eligibility, normalization, and persistence to the
application service.

README now includes the two helper commands, the CLI workflow, the MCP names,
and the current limits around complete scopes, watch/focused/compound runs,
snapshot updates, retries, and unittest subtests. The reusable
`docs/test-evidence-workflow.md` gives Crush the exact capture, record, episode,
inspection, consolidation, and fresh-session sequence.

## Verification

`cargo fmt --all -- --check`, `cargo check --all-targets --all-features`, and
the full `cargo test --all-targets --all-features --quiet` suite pass (228 unit
tests plus all integration suites). The CLI evidence help/discovery test
passes, and the MCP initialize/tool advertisement test passes with all three
new tool names and a live capability response.

## Remaining BP5 gate

A real Crush session still needs to execute each shipped helper, record the
bundle, complete an explicit episode, and exercise inspection, preview,
acceptance, and fresh-session context reuse. That qualification remains a
release gate and is not inferred from transport discovery tests.

**Status:** Implementation slice accepted; black-box qualification pending.
