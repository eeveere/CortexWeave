# Checkpoint 22: v0.2 Checkpoint API

## Result

PASS. Phase 4 exposes structured checkpoint creation and latest lookup through
transport-neutral context and facade services.

## Verified Behavior

- Checkpoints preserve their objective, completed work, decision IDs, open
  problems, related paths, related symbols, next action, and human-readable
  content.
- Creation validates an active workspace/session scope and an optional task in
  that same scope.
- Checkpoint decision IDs must be unique, nonempty decision memories in the
  requested workspace.
- The context service provides latest checkpoint lookup for workspace, session,
  and task scopes. A valid empty scope returns no checkpoint; missing or
  cross-workspace scope is rejected.
- Creation timestamps come from the service clock, keeping ordering testable and
  deterministic.

## Boundary

`ContextService` owns checkpoint validation and lifecycle rules.
`SqliteStorage` owns structured persistence and scoped latest queries.
`CortexWeaveService` exposes the same operations without MCP or CLI types.
Checkpoints remain resume state; later candidate and context-assembly phases may
choose when to include them but do not redefine their persistence lifecycle.
