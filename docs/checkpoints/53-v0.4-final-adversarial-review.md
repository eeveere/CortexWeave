# Checkpoint 53: v0.4 Final Adversarial Review

## Result

Breakpoint 15 is complete, but the v0.4 release gate is **not ready to pass**.
The review found five v0.4 blocker groups, five bounded hardening items, three
v0.5 items, and nine rejected concerns. The previously reported Breakpoint 14
pass is withdrawn: its repository evaluation proved that a mixed-language graph
could be built, but did not exercise the required structural query set.

No implementation fix belongs to this Sol/xhigh review pass. The accepted work
below is the complete input to Terra/high Final Hardening.

## Accepted v0.4 Blockers

### B1. Local import and module resolution is incomplete

Built-in analyzers emit raw module targets such as `./shared`,
`package.worker`, and `crate::shared::Engine`. `resolve_module` compares those
targets with qualified names and exact file stable keys, but the analyzers do
not supply source-relative, extension-aware, package-index, or external-root
aliases. An ordinary TypeScript import such as `./shared` therefore cannot
resolve to `src/shared.ts` through the current built-in path.

This is false structural absence and blocks import relationships, dependency
traversal, impact, and graph-aware context.

Accepted fix:

- Keep language and package path rules inside analyzers.
- Have analyzers emit deterministic normalized module candidates, aliases, and
  explicit external roots through the existing transport-neutral relationship
  contract.
- Keep the graph resolver generic: it matches normalized candidates and reports
  unresolved or ambiguous outcomes without guessing.
- Add end-to-end resolved, unresolved, external, ambiguous, and source-relative
  fixtures for Rust, Python, TypeScript, JavaScript, C#, and Go as supported by
  each analyzer's advertised capability.

### B2. Structural read bounds and neighbor semantics are not fully enforced

`StructuralService::neighbors` delegates to the general traversal operation
with the caller's depth, even though the CLI/MCP contract describes direct
neighbors. `load_seed_nodes` does not cap the number of explicit seeds, so a
facade caller outside the adapters can exceed the service's advertised node
bound before traversal begins. It also silently drops missing or
cross-workspace node IDs and returns a successful empty or partial result.

Accepted fix:

- Force `neighbors` to one hop, matching callers, callees, implementations, and
  tests.
- Reject an explicit seed list that exceeds the effective node limit.
- Require every requested exact node ID to exist in the selected workspace;
  return an actionable not-found error instead of a partial success.
- Add facade, CLI, and MCP coverage for depth, seed-count, missing-ID,
  cross-workspace-ID, and truncation behavior.

### B3. Test relationships overstate certainty and C# detection can leak

C# test annotation scans up to 256 bytes before a symbol. A test attribute on a
nearby prior declaration can therefore mark a following helper as a test. In
addition, every direct call made by a test symbol becomes a `Tests` edge with
confidence `0.9`, while adapter and context wording describes that association
as code the test "covers." A direct call is useful structural evidence, but it
is not proof of behavioral coverage.

Accepted fix:

- Bind C# test attributes structurally to the declaration they annotate.
- Preserve direct-call test associations, confidence, and provenance, but label
  them as likely/direct-call associations in domain metadata, context reasons,
  and user-facing descriptions.
- Add negative fixtures for adjacent attributed declarations, helper/assertion
  calls, framework wrappers, and non-test symbols in test files.

### B4. The real-repository and acceptance evidence is incomplete

`tests/real_repository_evaluation.rs` currently checks graph currency, nonzero
node and edge counts, multiple languages, and one arbitrary neighbor request.
Breakpoint 14 requires symbol lookup, callers, implementations, tests,
dependency traversal, impact, graph-aware context, and manual validation. The
current harness proves none of those query families on a known exemplar.

Accepted fix:

- Expand the evaluation harness to select named, reviewable exemplars for every
  required query family.
- Assert exact identities, paths, provenance, bounds, and conservative certainty
  rather than only nonzero counts.
- Run the acceptance edit and verify source revision, graph revision, affected
  facts, unrelated graph preservation, and fresh post-edit answers.
- Capture a manual sample and the repository identity in the release checkpoint.

### B5. Graph performance evidence is mislabeled and incomplete

The performance baseline assigns total initial indexing time directly to
`initial_graph_build_ms` and total single-file edit time directly to
`incremental_graph_update_ms`. Those are integrated timings, not isolated graph
measurements. Query operations have distributional samples, but build/update do
not yet record the required cold/warm distribution, hardware, v0.3 comparison,
or agreed regression budget.

Accepted fix:

- Add explicit timing around graph analysis/reconciliation, or rename the
  integrated metrics honestly and add separate graph timers.
- Capture p50/p95 for cold build, warm startup, incremental edit, and graph
  queries with fixture size, build mode, hardware, SQLite growth, and working
  set.
- Record the comparison baseline and release regression budget. Timing remains
  observational in variable CI; deterministic efficiency invariants remain
  assertions.

## Accepted Hardening

1. Preserve `failed_graph_target_revision` and `last_graph_error` while unrelated
   successful work leaves the workspace graph stale. Clear failure diagnostics
   only when the failed projection is repaired and the graph becomes current.
2. Replace graph-status and workspace chunk-count materialization with indexed
   SQL aggregate queries. This is v0.4 hardening; a full selective resolver
   redesign remains v0.5 unless the final budget forces promotion.
3. Normalize impact-path queries with the same canonical path rules used by
   workspace registration, including `.` components and separators.
4. Remove duplicated graph-tool sections from `docs/mcp-setup.md` and document
   direct-neighbor, likely-test, stale-read, and capability semantics precisely.
5. Report every optional integration explicitly and describe direct-call and
   dynamic-language capability limits without implying member-dispatch support.

## v0.5

1. Replace whole-workspace node loading and per-document reprojection with a
   selective, indexed resolver/reconciliation design after the v0.4 measurements
   identify the correct boundary. Promote this only if the accepted v0.4 budget
   cannot be met safely.
2. Add richer receiver/member dispatch, framework-aware test semantics, and
   other dynamic-language inference only behind new analyzer capabilities and

## Rejected Concerns

- **Stale facts reported as current:** rejected. Revision state, analyzer
  structural versions, current-only reads, and end-of-read snapshot checks guard
  the contract.
- **Cross-workspace leakage:** rejected. Reads are workspace-scoped and composite
  foreign keys/triggers enforce ownership.
- **Stable-key or cross-language collisions:** rejected for built-ins. Keys
  include normalized path and analyzer namespace, with workspace uniqueness and
  conflict rejection.
- **Orphan nodes or edges:** rejected. Transactional batches, foreign keys, and
  cascades preserve ownership and deletion integrity.
- **Ambiguity guessed as certainty:** rejected. Multiple candidates remain
  explicit and the resolver does not choose one silently.
- **Graph explosion after seed loading:** rejected. Traversal has node, edge, and
  depth ceilings, indexed adjacency reads, and explicit truncation; B2 covers the
  uncovered seed boundary.
- **Impact overclaiming:** rejected in the core contract. Impact is documented as
  reverse structural reachability with paths and confidence, not runtime or diff
  prediction. B3 covers the user-facing test wording exception.
- **MCP coupling:** rejected. The adapter calls application services and core
  graph modules contain no MCP types.
- **Context over-expansion:** rejected. Candidate, structural-fraction, node,
  edge, depth, and token budgets remain bounded with structural provenance.

## Final Hardening Boundary

Terra/high implements only B1-B5 and the five accepted hardening items, then
runs the complete v0.1-v0.4 acceptance suites, formatting, check, Clippy, all
targets/features, real-repository evaluation, performance qualification, and
`git diff --check`. v0.4 is not complete until those gates pass and the evidence
is recorded without relabeling integrated or inferred results as stronger facts.
