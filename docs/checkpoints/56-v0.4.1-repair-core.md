# v0.4.1 Repair Core Checkpoint

**Date:** 2026-08-29  
**Scope:** Phases 1–3 complete; stop before Breakpoint 1 concurrency review.

## Delivered

- Migration `0006_graph_repair_generations.sql` adds one durable repair owner
  per workspace and per-document graph projection manifests.
- Transport-neutral repair contracts and the application repair operation support
  `if_needed` and `force` without MCP dependencies.
- Reprojection verifies the persisted source hash, reuses the stored document
  and chunks, performs no embedding work, and persists graph facts, nodes, and
  manifests under the owning generation.
- Only an active owner whose complete expected analysis and physical projection
  manifests match may promote the graph revision to `Current`.
- Active, failed, and interrupted repairs reject all structural reads, including
  explicit stale reads. Semantic and lexical retrieval remain unchanged.

## Evidence

- A populated migration-`0004` fixture upgrades through migration `0006`.
- Missing graph projections repair to `Current` with zero embedding calls and no
  source-revision change.
- A forced repair reprojections a current workspace with zero embedding calls.
- Source drift records a durable failed generation and blocks stale structural
  reads.
- `cargo fmt --check`, `cargo check`, Clippy with warnings denied, and the full
  test suite pass (157 library tests, 25 integration tests; one deliberate
  real-repository evaluation remains ignored).
