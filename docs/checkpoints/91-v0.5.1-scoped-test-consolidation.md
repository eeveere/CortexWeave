# v0.5.1 Checkpoint 91: Scoped Test Consolidation

**Date:** 2026-09-04

**Breakpoint:** BP2

## Result

Normalized Vitest and unittest evidence now participates in deterministic
failure-to-verification consolidation. A test verification scope hashes the
exact profile/producer/runner/runtime, environment, language, selection,
settings, sorted parent inventory, and sorted verification-input states. Run
outcome, IDs, timing, errors, and artifacts are excluded from that scope.

A later pass covers the initial failure only when this fingerprint is equal.
Removing or renaming a case, changing the selected file/module/class, changing
settings or test/config/dependency bytes, or crossing profiles cannot verify
the original failure.

## Honest attempts

`AttemptResult::VerificationFailed` records a failed verifier observation when
compatible-only or incomparable signatures cannot establish exact recurrence
or a proven different failure. `StillFailing` remains restricted to equal
exact-capable signatures; `VerificationChangedFailure` requires comparable
exact-capable unequal signatures. Existing coarse Cargo and generic evidence
therefore no longer overstates a changed failure.

The consolidator is version 2. Existing accepted Experience rows remain
immutable. Migration 0014 expands the persisted verification kind with
`test_run` and the attempt result with `verification_failed`, preserving v0.5
rows through a transactional SQLite table replacement.

## Verification

Both profiles pass a native failure/action/failure/action/pass cycle, produce
an automatic verified-success proposal, persist one `test_run` terminal
observation, record the first compatible failed attempt as
`verification_failed`, and accept through SQLite. Controls reject missing-case
and changed-settings passes as ambiguous verification scope. Existing Rust
full-cycle, consolidation, repository, and native-delivery tests remain green.
