# Checkpoint 54: v0.4 Final Hardening

## Result

Terra/high Final Hardening resolves every accepted Breakpoint 15 blocker without
adding v0.5 orchestration or speculative language inference. All v0.4 release
qualification gates below pass.

## Blockers Closed

### B1. Deterministic local module resolution

- Built-in analyzers now emit normalized, analyzer-owned module candidates for
  source-relative files, source extensions, index files, Python dotted and
  relative modules, and Rust crate/self/super forms.
- JavaScript and TypeScript imports that name emitted `.js`, `.jsx`, `.mjs`, or
  `.cjs` files also publish their source-file candidates, permitting a source
  workspace import such as `../app.js` to resolve to `app.ts` deterministically.
- Explicit external roots are limited to declared safe cases (for example
  JavaScript `node:` and Rust standard-library roots). The generic resolver
  only matches candidates; it does not invent language rules.
- Regression coverage includes source-relative TypeScript, compiled-extension
  TypeScript, Python relative, and end-to-end local module resolution.

### B2. Bounded structural reads

- `neighbors` is always one hop.
- Exact seed lists that exceed the effective node bound are rejected.
- Every requested exact node ID must exist in the selected workspace; missing
  and cross-workspace IDs return an actionable error.
- Canonical path handling also collapses dot components for impact queries.

### B3. Conservative test associations

- C# test attributes are bound to the declaration they annotate, eliminating
  nearby-declaration leakage.
- Direct calls from test symbols remain useful `Tests` facts, but their
  metadata and all user-facing wording now describe a likely direct-call
  association rather than behavioral coverage.

### B4. Acceptance evaluation

`tests/real_repository_evaluation.rs` now verifies exact symbol lookup,
callers, implementations/inheritance, likely test associations, resolved local
dependencies, impact, graph-aware retrieval, candidate-pool retention, and
context output. It copies the selected repository into a temporary workspace,
so its acceptance edit cannot alter the source checkout. The test verifies the
content and graph revisions advance together, affected source is reindexed,
an unrelated graph node survives, and a fresh structural answer remains
available.

### B5. Honest performance evidence

The baseline reports nine-sample p50/p95 distributions and labels build and
update measurements as integrated index-and-graph work. It measures cold
initial build, warm reconciliation, incremental edit, exact lookup, one- and
two-hop traversal, impact, and graph-aware context. Deterministic assertions
remain limited to the incremental invariant: one changed fixture chunk causes
one embedding batch and a re-embedding ratio of 1.0.

The observed integrated p50/p95 values (milliseconds) were:

| Fixture | Initial build | Warm reconciliation | Incremental update |
|---|---:|---:|---:|
| Single-language | 27.14 / 39.20 | 9.15 / 13.40 | 29.13 / 32.35 |
| Mixed-language | 80.49 / 87.52 | 20.84 / 27.31 | 44.69 / 48.63 |

These are observational development-host measurements, not a CI latency gate.
Working-set sampling reported approximately 18–19 MB. Hardware inventory was
not available to the test process, so no hardware claim is recorded.

## Additional Hardening

- A failed graph target revision and its error diagnostic survive unrelated
  successful work until the failed projection reaches `Current`.
- Workspace status derives chunk and graph counts from SQL aggregates rather
  than materializing each graph entity.
- CLI and MCP documentation now have one graph-tool description with direct
  neighbor, stale-read, capability, and likely-test semantics.
- Optional integrations remain explicitly deferred: Git-diff seeded impact,
  diagnostic mapping, graph-aware working-set activation, inferred
  cross-language edges, and visualization.
- Unit tests ensure bounded hybrid search and context candidate selection retain
  available structural evidence without displacing required task/checkpoint/
  pinned items.
