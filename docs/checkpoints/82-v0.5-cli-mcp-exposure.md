# v0.5 Checkpoint 82: CLI and MCP Experience Exposure

**Status:** Complete

Phase 10 exposes the existing application-service Experience lifecycle through
the CLI and MCP without moving any consolidation, verification, lifecycle, or
ranking policy into a transport adapter.

## Delivered surface

- CLI episode start, association, close, abandon, inspection, and bounded list
  commands.
- CLI Experience preview, explicit consolidation acceptance, search, detail,
  explanation, assessment history, reviewed assessment, and read-only dispute
  proposal commands.
- MCP equivalents with explicit schemas, workspace selection through the
  existing policy, bounded event/evidence arrays, and bounded Experience search.
- Optional canonical active failure signatures for CLI and MCP context requests,
  preserving Experience as historical supplemental context.

## Mutation semantics

Episode mutations require `expected_version` and `request_key`. Consolidation
acceptance requires the exact fingerprint and proposal hash from preview. A
reviewed assessment requires caller-declared reviewer provenance, a reason, and
one to 64 Event IDs. Those inputs are recorded but not authenticated by an
adapter. Dispute proposals are read-only; no exposed tool silently applies a
dispute, refutation, or supersession.

## Evidence

- CLI help conformance covers all episode and Experience subcommands plus the
  required acceptance and assessment arguments.
- MCP conformance drives session/event/episode start, association, close, list,
  bounded-input rejection, empty Experience search, and rejected incomplete
  consolidation through JSON-RPC.
- The existing native full-cycle test remains the transport-neutral proof of
  deterministic extraction, consolidation, retrieval, and context behavior.
