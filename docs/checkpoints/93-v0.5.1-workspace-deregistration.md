# v0.5.1 Checkpoint 93: Safe Workspace Deregistration

**Date:** 2026-09-04

**Breakpoint:** BP3a

## Result

Workspace deregistration is now a two-step application-service operation.
Preview resolves an explicit selector, captures the exact workspace identity,
bounded scoped counts, lifecycle/graph state, and creates a five-minute plan.
Confirmation accepts only the exact workspace UUID, plan UUID, and request key.
SQLite rechecks the complete snapshot inside an immediate transaction before it
removes the workspace cascade and persists a minimal receipt outside that
cascade.

Receipts make a lost acknowledgement retryable without reviving the workspace.
Changed request keys conflict. Expired, missing, or changed previews return a
typed stale result and preserve all state. Plans and receipts retain IDs,
timestamps, and count summaries only; they never retain source files, Event
payloads, memory text, or Experience content.

The CLI exposes `workspace deregister-preview <selector>` and `workspace
deregister <workspace-id> --plan <plan-id> --request-key <key>`. MCP exposes
the equivalent two tools. Before MCP confirms deletion it stops and awaits the
workspace watcher under a lifecycle lock; it restarts the watcher when the
operation remains non-destructive.

## Verification

Tests cover an empty workspace, expired plans, stale snapshots, receipt-insert
rollback, idempotent acknowledgement retry, request-key conflicts, source-tree
preservation, fresh registration of the same root, and a populated workspace
containing indexed source, chunks, embeddings, graph data, memories, Events,
episodes, an accepted Experience, an assessment, and test-evidence receipts.
MCP tests prove the tools are discoverable, require a preview and exact IDs,
and preserve retry behavior.
