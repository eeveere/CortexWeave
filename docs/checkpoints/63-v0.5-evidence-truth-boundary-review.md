# v0.5 Evidence Truth-Boundary Review

**Date:** 2026-08-30

**Scope:** Breakpoint 1 on GPT-5.6 Sol/high

## Result

The evidence truth-boundary gate passes after tightening the Phase 1
contracts. A decoded value is a bounded, internally consistent producer report,
not authenticated truth, a task outcome, or a causal claim. No episode or
consolidator work was started.

The review made three contract corrections:

- process-backed observations now expose only the integer exit code and a
  mechanically derived `ExitedZero` or `ExitedNonzero` value;
- Rust compiler and Cargo-test reports now carry an explicit typed verification
  subject; and
- compiler diagnostics and source-change reports can no longer inject symbol
  keys. Symbol identity requires later deterministic structural resolution.

Decision D076 records the durable truth and signature boundary.

## Meaning of the Common Envelope

| Field | Evidence meaning |
|---|---|
| event ID and type | Stored event identity and declared event category. The decoder also requires the type accepted by the selected contract. |
| workspace, session, task | Stored scope. Typed evidence requires an explicit session; an optional task remains exactly as recorded. Scope does not prove the task succeeded. |
| recorded time | Stored event-envelope time, used only as temporal provenance. |
| contract and version | Exact decoder discriminator. There is no shape guessing or fallback to another decoder. |

These are durable facts about the stored event. They do not authenticate the
process or person that produced its payload.

## Meaning of Every v1 Payload Field

### External tool completion

| Field | Meaning |
|---|---|
| tool, operation | Bounded producer-selected labels; never raw command-line authority. |
| exit code | Producer-reported process exit observation. Zero is not task success. |
| error class | Optional producer classification for diagnostics; not automatically a signature component. |
| message | Optional bounded free text; display/diagnostic material only. |

This contract reports completion only. It is not verification evidence by
itself and has no verification subject.

### Rust compiler result

| Field | Meaning |
|---|---|
| subject kind/value | Producer-declared workspace, package, or target verified by the invocation; future rules must validate compatibility. |
| exit code | Producer-reported compiler process exit. The decoded process outcome is derived from it. |
| diagnostic level/code/message | Producer-reported compiler diagnostic. A nonzero exit requires an error; a zero exit rejects an error. Messages remain non-signature text. |
| diagnostic path | Optional normalized workspace-relative source path. |
| diagnostic line/column | Optional one-based reported location; column requires line. It is not historical identity. |

No symbol field exists. A later normalizer may resolve a path/location to a
symbol only through a deterministic capability and must retain that provenance.

### Cargo-test result

| Field | Meaning |
|---|---|
| subject kind/value | Producer-declared workspace, package, target, or test scope. A path is not an accepted Cargo-test subject. |
| exit code | Producer-reported Cargo process exit. The decoded process outcome is derived from it. |
| failure test name | Optional producer-reported failing test identity. |
| assertion class | Optional bounded producer classification, not raw assertion text. |
| failure message | Optional bounded diagnostic text; never task success or a raw signature component. |

A zero exit cannot carry failures. A nonzero result must carry at least one
failure observation, so compiler-only Cargo failures must use the compiler
contract rather than masquerading as a test failure.

### Generic verifier result

| Field | Meaning |
|---|---|
| verifier ID/version | Producer-declared rule identity. Decoder registration does not make the verifier trusted or registered for consolidation. |
| tool, operation | Bounded producer-selected invocation labels. |
| reported result | Producer assertion of pass/fail, required to agree with the exit code by the v1 contract. |
| exit code/process outcome | Producer-reported exit and its mechanical zero/nonzero derivation. Neither is task success. |
| subject kind/value | Producer-declared workspace, package, target, test, or workspace-relative path scope. |

Phase 3 must register the verifier rule and decide subject compatibility before
this report can support a verified experience.

### Source-change observation

| Field | Meaning |
|---|---|
| change | Producer-reported create, modify, remove, or rename, required to match the stored event type. |
| path/previous path | Normalized workspace-relative paths. Previous path is required only for a real rename. |
| workspace/document revision | Nonnegative producer-reported revision coordinates; not trusted current-state facts until storage validates or snapshots them. |
| content hash | Producer-reported lowercase BLAKE3 digest; explicit null is required for removal. |

The contract identifies reported content without accepting absolute or
temporary-root paths. It does not claim a symbol.

### User acceptance

| Field | Meaning |
|---|---|
| accepted | Must be the literal value `true`; rejection is not recoded as acceptance evidence. |
| accepted by | Bounded producer-reported actor label. The decoder does not authenticate it. |
| subject kind/value | Producer-declared acceptance scope. |

Ordinary trust requires authenticated ingress or later policy; a caller cannot
gain authority merely by choosing an actor string.

## Legacy and Signature Safety

Unversioned payloads remain explicitly unsupported and gain no inferred
fields. Unknown contracts and unavailable versions also remain unsupported;
malformed current contracts are invalid rather than downgraded to legacy.

Absolute paths are rejected anywhere a path is admitted. Raw messages,
diagnostic text, actor labels, tool labels, operation labels, environment data,
and command lines are outside the future signature allowlist. Phase 3 must use
versioned normalized components and prefer a less-specific or unsupported
signature to incorporating unstable or sensitive text.

## Fixture Proof

The six v1 fixture builders now assert every decoded observation field exactly,
not merely its envelope and contract. Adversarial fixtures additionally prove:

- process exit/detail conflicts fail visibly;
- compiler and test subject categories are restricted;
- injected symbol keys fail schema validation;
- absolute source paths fail;
- event/change mismatches fail;
- legacy input gains no typed meaning; and
- duplicate decoder ownership remains a startup error.

The next planned model boundary is Phase 2 on GPT-5.6 Terra/high.
