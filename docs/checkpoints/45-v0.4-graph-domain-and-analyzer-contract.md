# Checkpoint 45: v0.4 Graph Domain and Analyzer Contract

## Result

PASS. Phase 1 graph persistence and Phase 2 analyzer-contract work are complete.
No language-specific relationship extraction has been added.

## Durable Graph Foundation

- Migration `0005_graph_domain.sql` adds workspace graph revisions, per-document
  graph analysis state, graph nodes, source-owned relationship facts, resolved
  edges, unresolved diagnostics, and ambiguity candidates.
- SQLite enforces workspace-local source documents and edge endpoints with
  composite foreign keys. Triggers also validate optional node/chunk links and
  optional unresolved source nodes, which cannot be expressed by a nullable
  composite foreign key without losing the owning workspace.
- A graph edge optionally points to the durable relationship fact that supplied
  it. The source fact can therefore remain when a target is deleted or a
  resolver changes its conclusion.
- Node and edge upserts reconcile by logical key, retaining their stored UUIDs
  when the assertion is unchanged. No resolver or relationship extractor writes
  these tables yet.

## Revision Behavior

`workspace_graph_revisions` starts an empty workspace at `0/0/current`.
Reconciliation atomically advances `content_revision` only for a committed
document/chunk index change, and marks the graph stale. Deletion follows the
same rule. Embedding-only refreshes do not advance it. A graph updater can mark
work as updating, record an error target, or acknowledge an exact content
revision with a compare-and-set guard; an overtaken acknowledgement cannot mark
the graph current.

Migrating a populated v0.3 workspace preserves its existing data, gives each
existing document content revision `1`, and initializes graph state as `1/0` so
the missing graph is visible as stale. Initial graph construction remains able
to reuse compatible chunks and embeddings.

## Analyzer Contract

`LanguageAnalyzer::analyze` now returns a transport-neutral `AnalysisResult`:

```text
logical chunks
+ logical symbols
+ typed relationship facts
```

The six bundled structured analyzers derive logical symbols from their existing
pre-segmentation chunks and expose distinct structural extractor versions.
Generic fallback remains deterministic and emits chunks only. Every detailed
relationship capability is currently false, and every bundled analyzer returns
an empty relationship list. This is deliberate: Phase 2 creates the extension
point without fabricating structural certainty.

## Breakpoint 1: Graph Semantics Review

Accepted:

- source-owned facts carry target intent and provenance;
- an edge is a resolved projection rather than the evidence record itself;
- ambiguous and unresolved targets remain diagnostic records, never guessed
  local edges;
- external targets remain workspace-scoped when later extraction identifies
  them deterministically;
- confidence is bounded to `[0.0, 1.0]` in the database.

## Breakpoint 2: Analyzer Abstraction Review

**Can a new language expose relationships without modifying graph core?** Yes.
It implements the existing analyzer trait, returns normalized symbols and typed
relationship targets, and advertises only the capabilities it proves.

**Can a language expose only symbols and no calls?** Yes. The current bundled
analyzers demonstrate exactly that state: symbols are present, `calls` is false,
and no relationship is emitted.

## Regression Coverage

- graph-node upserts preserve identity and graph storage rejects cross-workspace
  edges and ambiguity candidates;
- source revisions advance only on committed source-index changes and an
  acknowledgement restores current state;
- v0.1/v0.3 data migrates without loss and starts with an explicitly stale
  populated graph;
- generic fallback emits no structural claims;
- every bundled structured analyzer emits symbols with no unproven
  relationships.
