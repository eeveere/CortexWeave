# v0.5.1 Checkpoint 94: External Test Capture

**Date:** 2026-09-04

**Breakpoint:** BP4

## Result

Two explicitly invoked external capture helpers now emit the frozen
`cortexweave.test_run_result` contract without adding a Node, Vitest, Python,
or unittest dependency to CortexWeave's Rust core. Each resolves its runner
from the selected workspace/runtime, runs a single bounded scope, records a raw
framework observation beside the normalized bundle, and refuses to overwrite
an existing capture artifact.

`integrations/vitest/capture_vitest.mjs` uses the qualified Vitest 4.1.10
custom-reporter API. It requires one workspace-relative test file, disables
snapshot update, starts a non-watch local run, and preserves actual case
outcomes, runner settings, and process exit. `integrations/unittest/
capture_unittest.py` uses only Python's standard-library `unittest` callbacks
for one complete module or `TestCase` class. It retains parent and subtest
observations separately and never installs a project dependency or rewrites a
test.

The emitted digests are bounded integrity identifiers accepted by the v1
decoder. They are provenance aids, not authenticated producer signatures.

## Verification

The Vitest helper ran against the selected emCP checkout with its installed
Node 24.19.0 and Vitest 4.1.10. It completed with exit code zero and preserved
seven passing cases from `tests/unit/hybrid-retrieval.test.ts`; its raw report
records `updateSnapshot: "none"`. The helper also preserved an incomplete
diagnostic bundle when the runner could not create Vite's temporary config
cache.

The unittest helper ran through PiHype's selected virtual-environment Python
3.14.7 interpreter against `tests.test_core.StagnationTests`, without pytest.
It completed successfully and emitted the normalized bundle and raw collector
artifact. Syntax checks pass for both JavaScript modules and the Python helper.
