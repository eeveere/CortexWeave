# v0.5 Checkpoint 73: Consolidation Idempotency and Transaction Proof

**Date:** 2026-08-30

**Scope:** Breakpoint 6 on GPT-5.6 Terra/high

## Result

Automatic acceptance now binds its write transaction to the exact immutable
episode input that the service previewed.  Before an Experience row is written,
the transaction re-reads ordered membership and every event's ID, stored type,
and BLAKE3 hash of canonical JSON payload.  A scope or identity mismatch is a
conflict and writes no Experience material.

The canonical JSON routine is shared by proposal hashing and transaction
revalidation.  Its version is an explicit immutable Experience field and is
included in the input fingerprint.  The extractor and summary-renderer
versions remain explicit immutable fields as well.

SQLite acceptance uses `BEGIN IMMEDIATE`.  That acquires the one writer slot
before it performs the revalidation reads, avoiding deferred-transaction
upgrade lock failures.  Concurrent service instances therefore serialize; the
later writer observes the unique fingerprint and returns the same canonical
Experience after checking its material proposal hash.

## Proofs

Focused durable tests cover one episode accepted once, twice, and ten times;
two concurrent service instances; and a newly opened storage instance after
restart.  Each produces one equivalent Experience, attempt set, evidence-link
set, FTS row, and retained assessment history.

The same suite proves that:

- mismatched re-read input, stale versions, and cross-workspace input identity
  are rejected with no Experience rows;
- an invalid evidence foreign key rolls the whole aggregate and FTS projection
  back;
- a distinct persisted extractor version is traceable as a distinct
  interpretation;
- canonicalization version is preserved on reload; and
- raw event rows remain byte-for-byte equivalent throughout acceptance.

No Phase 6 retrieval work is included in this checkpoint.
