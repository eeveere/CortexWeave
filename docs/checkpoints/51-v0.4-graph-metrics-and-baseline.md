# v0.4 Phase 15: Graph Metrics, Doctor, and Performance Baseline

Phase 15 makes graph state observable without broadening graph semantics.

## Implemented

- Workspace status now includes graph revision and staleness, node and edge
  totals, unresolved relationship count, and per-indexed-language active
  analyzer capabilities.
- `cortexweave graph status <workspace-id>` and MCP `graph_status` expose the
  same transport-neutral application-service report.
- `doctor` evaluates every registered workspace graph projection and includes
  the underlying report. A stale, failed, missing, or unreadable graph is an
  unhealthy diagnostic result; no registered workspaces remains healthy.
- The performance baseline fixture now reports p50/p95 for cold initial
  index-and-graph build, warm reconciliation, incremental index-and-graph
  update, exact lookup, one- and two-hop traversal, impact, graph-aware
  context, and SQLite growth for single- and mixed-language fixtures. Build and
  update measurements are explicitly integrated source-index plus graph work;
  they are not mislabeled as graph-only latency.

## Verification

- Service status coverage proves a reindexed Rust workspace reports a current
  graph and the active Rust capability set.
- MCP coverage proves `graph_status` is advertised and returns current graph
  counts for an indexed fixture.
- The baseline repeats each measured operation nine times and emits p50/p95
  rather than using a timing threshold in CI. Release qualification records the
  host, build mode, fixture size, cold/warm state, SQLite growth, and agreed
  regression budget beside the emitted report.

## Boundary

Phase 15 is complete. Phase 16 documentation expansion, release notes, and
the v0.4 acceptance gate remain the next planned work. Graph observations and
later orchestration are still out of scope.
