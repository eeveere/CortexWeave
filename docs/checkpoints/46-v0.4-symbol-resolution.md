# v0.4 Phase 3: Symbol Registry and Resolution

Phase 3 adds a transport-neutral, workspace-scoped symbol registry and a
deterministic resolver. It intentionally stops before Phase 4 relationship
extraction.

## Implemented

- Core file nodes and analyzer-namespaced symbol nodes are reconciled per
  document in a SQLite transaction.
- Stable logical keys preserve node UUIDs across body and offset changes.
- Deleted symbols are removed; stable-key collisions between documents reject
  and roll back the full registry update.
- Indexed lookup supports stable key, node ID, qualified name, simple name, and
  source document, always scoped by workspace.
- Resolution supports local stable keys, exact qualified symbols, enclosing
  containers, source-document and unique workspace names, exact modules/files,
  analyzer-provided aliases, declared external roots, explicit external
  targets, and explicit unresolved targets.
- Outcomes distinguish resolved, ambiguous, external, and unresolved. Resolved
  and ambiguous outcomes retain the applied precedence basis; ambiguity can
  retain both local candidates and canonical external targets.
- Resolution is deterministic and structural only. It performs no semantic,
  fuzzy, case-insensitive, or cross-language guessing.

## Resolution Torture Test

`tests/resolution_torture.rs` covers:

- the same function name in two modules;
- the same method name in different classes;
- aliases and import renames;
- nested modules and local stable keys;
- ambiguous local imports and ambiguous external aliases;
- declared external packages versus missing targets;
- UUID preservation followed by target deletion;
- cross-workspace target and source-context isolation; and
- rollback on a cross-document stable-key collision.

The gate requires every ambiguous case to remain explicit. Deleted and missing
targets must be unresolved, and a symbol in another workspace must never appear
as a candidate.

## Boundary

Phase 3 does not extract imports, calls, references, inheritance, or test
relationships and does not project relationship facts into edges. Those begin
at Phase 4 under the next canonical model setting.
