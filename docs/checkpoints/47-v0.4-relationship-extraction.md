# v0.4 Phases 4–7: Capability-Gated Relationship Extraction

Phases 4–7 add source-owned structural facts to the enabled tree-sitter
analyzers. They do not yet persist or resolve those facts into graph edges;
that integration is Phase 8.

## Implemented

- Every structured analyzer emits exact `Contains` and `DeclaredIn` facts.
- Rust, Python, TypeScript, JavaScript, C#, and Go emit parser-derived import
  and dependency facts. Export facts are advertised only by Rust,
  TypeScript, JavaScript, and Go.
- Direct identifier calls emit `Calls` and `References` at 0.9 confidence.
  Receiver/member dispatch is deliberately omitted.
- Rust `impl Trait for Type`, Python and JavaScript/TypeScript `extends`, and
  TypeScript `implements` emit inheritance facts. C# base lists emit only
  `UsesType` until type roles can be established safely.
- Explicit test syntax creates test nodes. Direct calls from tests emit `Tests`
  at 0.9 confidence. No co-location or name-based coverage heuristic is used.
- Capability flags now describe exactly the supported relation classes; generic
  fallback still emits no structural claims.

## Breakpoint Evidence

`tests/relationship_extraction.rs` covers:

- the mixed Rust/Python/TypeScript/C# module graph;
- direct calls and references while rejecting member-dispatch claims;
- Rust/Python/TypeScript/C# inheritance and implementation behavior; and
- Rust and JavaScript explicit test nodes with direct-call test relationships.

The suite rejects false certainty: unsupported relationship classes remain
unadvertised, and uncertain syntax produces no stronger fact.

## Boundary

Source facts are still analyzer output. Phase 8 must reconcile symbols and
facts transactionally with documents, resolve affected targets, preserve
unchanged facts and edge UUIDs, and maintain graph revision watermarks.
