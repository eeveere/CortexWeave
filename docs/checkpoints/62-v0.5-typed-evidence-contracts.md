# v0.5 Typed Evidence Contracts

**Date:** 2026-08-30

**Scope:** Phase 1 on GPT-5.6 Terra/high

## Result

Phase 1 is complete. CortexWeave now decodes eligible raw events through a
versioned, deterministic contract registry without changing stored event
payloads or assigning any episode, experience, assessment, or outcome.

The registered v1 contracts are:

- external tool completion;
- Rust compiler result;
- Cargo test result;
- generic registered verifier result;
- source-change observation; and
- user acceptance.

Each decoded value preserves its event, workspace, session, optional task, and
timestamp envelope. Every evidence-bearing contract requires an explicit
session; payload identifiers, diagnostic/failure lists, textual fields, paths,
and hashes have bounded, contract-specific validation. The source-change
contract also requires a matching file event type and distinguishes an observed
absent content hash from a hash value.

Unversioned legacy payloads, unknown contracts, and unavailable versions are
reported as explicit unsupported results. Malformed, oversized, conflicting,
or provenance-incomplete payloads return structured invalid results. The
registry uses the `(contract, version)` pair as its unique key and rejects
ambiguous registrations at startup.

`CortexWeaveService` exposes read-only evidence diagnosis for adapters and
future application services. Recording remains raw and append-only; diagnosis
does not rewrite or otherwise mutate the supplied event.

## Verification

- Contract unit coverage exercises all six valid v1 payloads, malformed and
  oversized fields, incompatible event types, legacy/unknown contracts,
  provenance enforcement, and duplicate registration rejection.
- The facade test verifies typed diagnosis without raw-event mutation and
  confirms the recorded JSON is preserved exactly.

## Deliberately Deferred

This phase does not add migrations, persistent evidence tables, episode
membership, experience creation, rule evaluation, failure normalization,
search, context injection, CLI commands, or MCP tools. A decoded result is
only an observation with declared scope; it is not success attribution or an
experience claim.

The next planned boundary is Breakpoint 1: GPT-5.6 Sol/high review of the
contract semantics before Phase 2 persistence begins.
