# Checkpoint 20: v0.2 Temporal Retrieval

## Result

PASS. Phase 3 provides deterministic, transport-independent temporal retrieval
over code, documents, memories, events, task state, and session state.

## Verified Behavior

- Queries filter by created and modified timestamp bounds.
- Recent windows accept hours or days and reject zero or unrepresentable values.
- Current and previous session scopes resolve within the requested workspace and
  apply before the result limit.
- Source-type filters and workspace scope apply in SQLite before bounded
  selection.
- Superseded memories are excluded by default and explicitly available when
  requested.
- Each result includes provenance, timestamps, freshness, and a configurable
  half-life recency score.
- Current source truth ranks ahead of more recent historical evidence, so
  recency cannot dominate provenance.

## Boundary

`ContextService` translates temporal query intent into validated bounds and
deterministic source-aware ordering. SQLite produces the normalized candidate
stream and owns filter execution. `CortexWeaveService` exposes the operation
without MCP or CLI types; adapters remain unchanged in this phase.
