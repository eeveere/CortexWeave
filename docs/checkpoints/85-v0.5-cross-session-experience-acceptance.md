# v0.5 Checkpoint 85: Cross-Session Experience Acceptance

**Status:** Complete

Breakpoint 11 passes through the transport-neutral native service contract.

Session A creates an explicit debugging episode containing a typed E0308
failure, one failed attempt, a second attempt, and a deterministic passing Rust
compiler observation. Consolidation preserves the exact workspace, session,
task, episode, and Event provenance; both attempt outcomes; deterministic
verification evidence; and a summary that describes only observed
verified-after ordering, never unsupported causation or current truth.

Fresh Session B begins without Session A messages. Its current indexed source,
active task, and newly recorded matching failure all remain selected ahead of
the bounded historical Experience. The current failure normalizes to the same
failure key as Session A, and exact Experience search returns the prior record
in bounded top-k. Historical content stays within its independent Experience
budget and retains `historical_supplemental` authority.

A separately registered workspace returns no Experience for a lexical control
query. Session A Events and transcript-only metadata are absent from Session B's
packet. Repeating acceptance with the same fingerprint and proposal hash returns
the original immutable Experience ID.
