# Checkpoint 44: v0.4 Architecture Audit

## Result

PASS. The v0.3 architecture has a clean layering seam for v0.4 graph state, and
the identity, ownership, revision, stale-read, structural-versioning, and
workspace-isolation contracts are accepted in D045-D050.

## Baseline Findings

- `LanguageAnalyzer` currently returns normalized logical chunks. Tree-sitter
  values remain private, and the registry already keeps language selection out
  of indexing core. The output does not yet have distinct symbol or relationship
  collections, and the broad `relationships` capability is not precise enough
  for v0.4.
- Structured analyzer stable keys encode normalized relative paths, containing
  symbols, kinds, names, signatures for overload disambiguation, and the Go
  receiver where applicable. They are suitable inputs to graph identity before
  embedding segmentation, but exact duplicate signatures still use a
  source-order ordinal and cannot promise identity across reordering.
- The embedding segmenter may turn one logical chunk into several persisted
  chunks and may replace that tree when provider capacity policy changes. Graph
  identity therefore cannot use persisted chunk UUIDs or `::segment:N` keys.
- Document reconciliation analyzes and embeds outside SQLite, rereads the source
  before commit, and atomically replaces document/chunk/embedding state. It has
  per-path process locks but no durable workspace content revision, dirty-graph
  ledger, graph watermark, or graph failure state.
- File events are persisted after watcher reconciliation and may fail
  independently. Their timestamps and UUIDs are not a monotonic source sequence
  and cannot drive graph consistency.
- Context assembly currently reads local parent/sibling metadata directly from
  storage and marks persisted code as current by source type. v0.4 graph
  expansion must move behind `StructuralService` and carry graph snapshot state
  separately from content freshness.
- Working-set entries and pins use polymorphic source IDs and do not own source
  lifecycle. v0.4 core graph work must not insert graph nodes into the working
  set or mutate attention automatically.

## Accepted Layering

```text
language analyzer
  -> normalized chunks + symbols + typed relationship facts
  -> graph indexer
  -> graph storage + deterministic symbol resolver
  -> structural service
  -> retrieval / context / impact / navigation
  -> CortexWeaveService
  -> CLI / MCP / native callers
```

SQLite remains the only transaction owner. Source content remains authoritative;
the graph is a replaceable derived index. Graph domain types and services remain
transport-neutral, while the indexing core remains language-neutral.

## Required Identity Fixtures

### Logical Symbol Versus Embedding Segments

Index a function large enough to split into multiple embedding chunks. Reindex
under a different segmentation capacity with unchanged source and analyzer
symbol output.

Expected:

- one graph symbol exists before and after;
- its graph node UUID and logical key remain unchanged;
- segment keys and chunk UUIDs may change without entering graph identity;
- unchanged relationship fact and edge UUIDs are preserved;
- embeddings are replaced only as required by segmentation compatibility.

### Body-Only Edit

Use `A calls B` plus unrelated `C`, then edit only the body of `B` without
renaming it or changing the call relation.

Expected:

- the content revision advances and graph state becomes non-current until the
  new revision is acknowledged;
- the graph node UUID for `B` and the `A -> B` fact and edge UUIDs survive;
- the unchanged edge row is not deleted and reinserted;
- `C` graph rows and embeddings remain untouched;
- after graph reconciliation, both workspace revision watermarks match.

### Names, Containers, Languages, and Workspaces

Create identical function and method names in different containers, two
supported languages, and two workspaces, including identical relative paths.

Expected:

- container-qualified analyzer keys distinguish methods;
- analyzer namespaces distinguish otherwise identical cross-language keys;
- workspace-scoped uniqueness distinguishes identical repositories;
- exact duplicate signatures receive deterministic unique occurrence keys while
  their source order is unchanged;
- SQLite rejects a local edge or ambiguity candidate whose endpoint belongs to
  another workspace.

### Rename and Delete

Resolve a source-owned fact from `A` to `B`, then rename and later delete the
document that owns `B`.

Expected:

- rename removes the old path-owned node and creates a new identity; v0.4 does
  not claim inode or Git continuity;
- the fact owned by `A` survives target deletion;
- its resolved edge is removed and the fact becomes unresolved unless the new
  target can be deterministically resolved;
- deleting `A` removes its fact and any projected edge.

## Required Revision Fixtures

### Transaction Rollback

Inject failure before a document reconciliation transaction commits and, in a
separate case, before a graph reconciliation transaction commits.

Expected:

- document failure changes neither source rows nor `content_revision`;
- graph failure exposes no partial node/fact/edge update;
- graph failure preserves `graph_content_revision` and the last committed graph;
- the target revision and error are observable.

### Failed and Retried Graph Catch-Up

Commit content revision `N + 1`, fail graph reconciliation, then retry.

Expected:

- graph state is `Error`, with content at `N + 1` and graph at `N`;
- current-only structural reads reject the graph;
- explicitly allowed stale reads are labeled with both revisions;
- a successful retry atomically advances the graph watermark and clears the
  current-target error.

### Concurrent and Coalesced Revisions

Commit two document updates in one workspace while graph work overlaps, and
attempt to commit the older graph analysis after the newer content revision
exists.

Expected:

- content revisions are unique and monotonic;
- the overtaken graph batch cannot mark the workspace current;
- a later batch may advance directly to the newest snapshot only after applying
  the complete cumulative dirty set and affected resolutions;
- no intermediate mixed graph is reported as current.

### Structural Extractor Version Change

Change only one analyzer's structural extractor version with source, logical
chunks, segmentation, embedding model, and dimension unchanged.

Expected:

- the workspace becomes structurally stale even when the two content watermarks
  are equal;
- graph analysis reruns only for affected documents;
- `content_revision`, chunk UUIDs, and embeddings remain unchanged;
- per-document applied structural version updates, unchanged identities survive,
  and graph state returns to `Current`.

### v0.3 Migration and Initial Build

Migrate one populated v0.3 workspace and one empty workspace.

Expected:

- all v0.3 documents, chunks, embeddings, memories, events, sessions, tasks,
  working sets, pins, and checkpoints survive byte-for-byte;
- the populated workspace starts with a nonzero content snapshot, a zero graph
  watermark, and non-current graph state;
- the empty workspace may start current at revision zero;
- the first graph build advances only graph state and does not re-embed
  compatible chunks.

### Generic Fallback

Index an unsupported text document with deterministic generic chunking.

Expected:

- core may create the file node, but the analyzer emits no symbol or
  relationship claim;
- a per-document graph-analysis record still acknowledges the configured
  structural version and content revision;
- the workspace can become current without fabricated `UnknownSymbol` edges.

## Phase 1 Entry Gate

Phase 1 may add graph domain and SQLite storage types only after preserving these
contracts. Relationship extraction remains out of scope until Phase 2. The next
scheduled implementation model is GPT-5.6 Terra with high reasoning effort.
