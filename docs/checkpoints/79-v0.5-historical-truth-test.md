# v0.5 Checkpoint 79: Historical Truth Test

**Date:** 2026-08-31

**Scope:** Breakpoint 9 on GPT-5.6 Sol/high

## Result

The historical-truth scenario passes after three adversarial corrections.

First, dispute proposal input now has to be genuinely later evidence. Every
recurring event must decode and normalize to the exact signature and must have
been recorded strictly after the prior verified-success Experience was created.
The original failure event can no longer be replayed as a false recurrence.

Second, Experience detail and historical search expose an explicit normal-context
eligibility projection. A disputed Experience reports `eligible: false`, its
`disputed` lifecycle, and `disputed_lifecycle` as the reason. Ordinary search
returns active eligible Experiences only; explicit historical inspection returns
the excluded Experience and its later assessment.

Third, the storage append operation is crate-private, and a new additive migration
rejects narrow deletion of assessments and their evidence. The migration also
corrects episode-membership deletion enforcement so the documented complete
workspace cascade remains possible while narrow historical deletion stays
forbidden.

## Historical Truth Assertions

- A proposal alone leaves Experience A active and writes no assessment.
- A replay of A's original failure creates no proposal.
- A later exact recurring failure creates a deterministic dispute proposal.
- Reviewed dispute makes A ineligible for ordinary search.
- Historical search returns A with historical-inspection admission.
- Detail inspection returns A's original summary, evidence links, immutable
  source event, later assessment, disputed lifecycle, and explicit exclusion
  reason.
- Direct assessment/evidence deletion fails; complete workspace deletion still
  cascades.

Breakpoint 9 is complete. Phase 9 remains unstarted.
