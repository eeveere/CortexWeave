# v0.4 Phase 8: Incremental Graph Reconciliation

Phase 8 connects normalized analyzer output to the durable graph while keeping
source indexing, embeddings, graph freshness, and dependent resolution
explicitly separated.

## Implemented

- `GraphIndexer` prepares proposed workspace nodes and durable relationship
  facts, resolves only the affected facts against that proposal, and submits a
  single graph reconciliation batch.
- SQLite owns the complete transaction for nodes, facts, resolved edges,
  unresolved/ambiguous projections, candidates, per-document analysis state,
  and the graph watermark.
- Every batch uses a content-revision compare-and-swap plus a same-revision
  update-ownership token. Superseded work writes nothing and is rebuilt against
  the newer workspace or graph snapshot.
- Source deletion and surviving-dependent reprojection are one transaction, so
  failure cannot leave a partially deleted structural view.
- Retained node, fact, and resolved-edge identities are preserved. Body-only
  target edits do not rewrite dependent edges or unrelated nodes.
- Resolver-visible candidate changes trigger targeted re-resolution for
  additions, ambiguity, renames, type/language changes, and deletions.
- Graph-analysis errors preserve the prior graph, label the current revision as
  `Error`, and can be retried without regenerating compatible embeddings.
- Indexing no-op detection now includes analyzer structural-version and graph
  analysis compatibility.
- Workspace freshness checks the structural version expected by the active
  analyzer registry for every document, so a partial structural-version rebuild
  remains visibly stale.

## Breakpoint 7 Evidence

`tests/incremental_graph_reconciliation.rs` proves the A-calls-B/C-unrelated
fixture across:

- exact no-op reconciliation with unchanged graph rows and embeddings;
- a B body edit with the A→B edge UUID preserved and C byte-for-byte untouched;
- a second B candidate producing an explicit ambiguity;
- deletion of the duplicate restoring deterministic resolution;
- B rename removing the old node and reprojecting A as unresolved;
- rename recovery and final B deletion; and
- graph failure followed by a graph-only retry that preserves the previous edge
  and reuses A's stored embedding; and
- a structural-version-only workspace rebuild that preserves content revision,
  embeddings, and resolved-edge identity while remaining stale until all
  documents use the configured version.

The storage tests `stale_graph_compare_and_swap_does_not_mutate_the_graph` and
`same_revision_graph_batches_require_the_current_update_token` prove that an
overtaken target cannot write nodes or advance the watermark, including when
two graph-only batches share a content revision.
Every successful fixture step verifies equal content and graph watermarks in
`Current` state.

## Boundary

Phase 8 persists structural truth and freshness but exposes no user-facing
traversal API. Phase 9 must add the bounded, current-by-default structural
service without moving SQL or resolver policy into adapters.
