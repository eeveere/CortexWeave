# v0.5 Episode Domain and Persistence

**Date:** 2026-08-30

**Scope:** Phase 2 on GPT-5.6 Terra/high

## Result

Phase 2 is complete. CortexWeave now has an explicit, session-bound episode
domain for organizing raw activity without interpreting it as an experience,
success claim, memory, or causal explanation.

`Episode` records workspace, required session, optional exact-session task,
declared activity type, lifecycle, creator, title, optimistic version, and
terminal time. `EpisodeEvent` persists ordered primary event membership. The
initial lifecycle is open, closed, abandoned, or invalid; the native facade
intentionally exposes start, add events, close, abandon, get, and bounded list
operations only.

## Durable Boundary

Migration `0007_episode_domain.sql` adds only the episode foundation:

- composite uniqueness on existing event and task scope needed for safe foreign
  keys;
- `episodes`, `episode_events`, and `episode_mutation_requests`;
- one primary workspace-scoped membership per event;
- unique ordinal per episode;
- scope/lifecycle/index constraints; and
- SQLite triggers that reject membership for non-open episodes and reject
  session or null-safe task mismatch.

An episode mutation reserves a durable request key and hash inside the same
SQLite transaction as the optimistic version update and membership insert or
terminal transition. Replaying the exact key and hash is idempotent; reusing a
key with different operation/content is a conflict. A stale add or close is a
typed conflict, never a silent overwrite.

Application services perform readable validation first, including bounded
ordered input, duplicate event IDs, workspace/session/task scope, and title or
request-key bounds. Database constraints repeat the essential provenance and
lifecycle protection so adapters and service sequencing cannot bypass it.

## Verification

- Domain/facade coverage verifies exact scope, caller order, idempotent replay,
  request-key conflict, terminal immutability, bounded listing, and closed
  timestamps.
- Concurrent same-version associations prove one commit and one conflict.
  Concurrent add/close proves either an explicitly closed empty episode or an
  open episode retaining the committed member; neither path silently omits a
  committed event.
- Repository coverage exercises the SQLite membership trigger, ordinal storage,
  and terminal-membership trigger directly.
- A populated migration-0006 database upgrades with legacy events unchanged,
  zero fabricated episodes, and zero fabricated memberships.

## Deferred

This phase does not normalize failures, decode events during membership,
consolidate episodes, create experiences, snapshot code or graph state, add
experience search/context, or expose CLI/MCP episode commands. Legacy and
unsupported events may be explicit episode members as raw activity, but they
gain no typed verification or signature meaning.

The next planned boundary is Breakpoint 2: GPT-5.6 Sol/high episode-semantics
torture test.
