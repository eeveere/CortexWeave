# v0.5 Experience Architecture Audit

**Date:** 2026-08-30

**Scope:** Breakpoint 0 on GPT-5.6 Sol/xhigh

**Baseline:** committed `main` at `2ea4d9a`, including v0.4.1 implementation
commit `176c143`; the working tree was clean when the audit began.

## Result

Breakpoint 0 is complete. The committed v0.4.1 substrate can support the
Verified Experience Core without collapsing events, memories, current code,
graph state, and experiences into one domain. No stop condition in the v0.5
release boundary is active.

The audit did identify material planning corrections. The v0.5 plan now:

- fixes `0007` as the first v0.5 migration;
- treats every v0.4.1 event payload as unversioned legacy input until a
  registered decoder validates its complete shape and provenance;
- requires exact session and null-safe task equality for primary episode
  membership;
- adds durable episode mutation request identity;
- separates workspace and document revision identity in historical snapshots;
- limits initial evidence sources to events and immutable code/graph snapshots;
- separates consolidation input identity from the material proposal hash;
- adds the missing strength, graph-snapshot, and assessment-evidence rows to the
  persistence outline;
- makes experience context budget reclamation one-way in favor of current
  evidence.

Decisions D069 through D075 record the accepted architecture. No migration,
domain type, decoder, service, CLI command, or MCP tool was implemented at this
breakpoint. Phase 1 begins only after the planned switch to Terra/high.

## Audited v0.4.1 Seams

### Workspace, session, and task provenance

`workspaces.id` owns every persistent domain. Sessions have composite identity
`(id, workspace_id)`. Tasks may omit a session, but when present their
`(session_id, workspace_id)` foreign key is enforced. Memories, events,
checkpoints, working-set entries, and pins separately reference workspace,
session, and task.

`CortexWeaveService::validate_provenance` rejects a session or task from another
workspace and rejects mismatched task/session pairs when both are supplied.
Context mutations apply the stricter rule that a scoped task must belong to the
specified session. The database does not currently express task/session
equality as one composite event constraint, so the v0.5 migration needs:

- a unique task key over `(id, workspace_id, session_id)` for episode task
  ownership; and
- episode-membership triggers that compare the stored event's session and task
  to the episode with null-safe equality.

The initial episode rule is intentionally strict. An event must have the
episode's explicit session and exactly the episode's optional task. An event
with a task but no session, or a session-less watcher event, is not eligible as
a primary member.

### Event envelope and emitted payloads

`CortexEvent` is an append-only application/domain envelope with UUID, workspace,
optional session/task, `EventType`, arbitrary JSON payload, and creation time.
Storage inserts and reads events; there is no event update or event-delete
application operation. Workspace deletion remains the complete-domain cascade.

The implemented payload producers are not typed v0.5 contracts:

| Producer | Event | Stored shape | Provenance consequence |
|---|---|---|---|
| file watcher | create/modify/remove/rename | `path`, reconciliation `status`, and added/modified/removed/embedded counts | no session or task; raw activity only |
| watcher rescan | `file_modified` | `rescan`, reason, file counts, failed paths, removals, embedded count | no session or task; raw activity only |
| native hydration override | `context_hydration_override` | reason, chunk IDs, source path/symbol and score provenance, packet source IDs | session/task scoped, but not failure or verification evidence |
| MCP `event_record` | caller-selected event type | arbitrary caller JSON | provenance is facade-validated; payload contract is not |

The native-harness tests also record external-tool, compiler, and test events
with only `{ "ok": true }`. Those fixtures prove adapter-independent event
recording, not a verification contract. Phase 1 must introduce explicit
contract and version identity and must reject event type or `ok` alone as proof
of a scoped success.

Existing events need a composite unique index on `(id, workspace_id)` before
`episode_events`, `experience_evidence`, and assessment evidence can use
workspace-scoped foreign keys. No legacy event is rewritten or auto-associated.

### Memory truth, trust, claims, and supersession

Memory remains an explicit durable-claim domain. Human-authorized memory must
enter as `Trusted`. Imported memory must enter as `Unreviewed` with nonempty,
nonoverlapping source segments. A review atomically compare-and-swaps the trust
state and appends `memory_trust_reviews`; only `Trusted` or `Rejected` are valid
review results. Structured claims remain an optional key/value pair.

Supersession is an explicit reviewed operation between trusted memories in one
workspace. SQLite checks cycles inside the insertion transaction. Context and
resume paths exclude untrusted and superseded memories where eligibility
matters. The read-only memory consolidation analyzer makes no durable merge.

Experience does not extend `MemoryKind`, mutate trust, reuse memory
supersession rows, or promote an inferred lesson. Initial experience evidence
also does not add unused memory/checkpoint source variants merely for future
extension.

### Checkpoints and resume behavior

Checkpoints are structured session-bound records with an optional matching task,
objective, completed items, trusted decision-memory IDs, open problems, paths,
symbols, next action, and creation time. They are append-only and queryable by
workspace, session, or task. Creation validates active-session provenance and
decision existence.

Resume selects an explicit or deterministic recent session/task, then uses
bounded historical inputs: at most 32 memories, 128 events, and 50 recent
paths. It produces a normal bounded context packet. v0.5 experience reuse is a
new context source and search path; it must not overload checkpoint content or
pretend the resume transcript itself is an experience.

### Code and graph identity, deletion, and revisions

Current code and graph rows are derived, mutable projections:

| Domain | Current logical uniqueness | Reconciliation behavior |
|---|---|---|
| document | workspace + normalized relative path | row updated or removed; owns current content hash and document revision |
| chunk | document + analyzer stable key | unchanged rows/embeddings preserved; changed or removed rows reconciled |
| graph node | workspace + stable key | current node may be retained, updated, or deleted |
| relationship fact | workspace + source document + relationship key | source-owned fact is replaced with its document projection |
| edge | workspace + relationship key | resolver projection may retain identity, retarget, or disappear |

`workspace_graph_revisions` separates workspace content revision from graph
content revision and records graph schema/state. Documents also have their own
content revision. `graph_document_states` records analyzer and structure
identity. `graph_document_projections` records per-document projection counts.

Graph repair is a durable fenced generation. Active, failed, or interrupted
generations block all structural evidence reads, including explicit stale
reads. A coherent stale graph can be read only when no incomplete in-place
generation has begun. Structural operations recheck the workspace snapshot and
reject a revision change during the read.

A graph node UUID, chunk UUID, or single ambiguous `content_revision` field is
therefore insufficient historical identity. D071 fixes the snapshot contract:
workspace revision, document revision/hash, logical stable keys, content hash
and range are copied in bounded form; graph evidence additionally snapshots the
graph/analyzer/structure identity. Current UUIDs may be recorded only as
observed provenance.

### Structural capability and freshness

`StructuralService` owns current/stale checks, exact symbol/path lookup, typed
one-hop relations, bounded traversal, and impact. Core hard ceilings are 1,000
nodes, 5,000 edges, and depth 8; defaults are 50, 100, and depth 2. Results
carry the workspace graph snapshot, effective limits, typed paths, confidence,
and truncation state.

Language analyzers own syntax and normalized relationships. The structural and
indexing cores do not interpret Rust compiler output, Cargo tests, episode
semantics, or experience meaning. Phase 1 decoders and later failure
normalizers remain pluggable services outside indexing.

### Context candidates, scoring, explanation, and budgeting

The v0.4.1 context domain has code, document, memory, event, task-state,
session-state, and bounded `Other` sources. A candidate carries source identity,
content, path/symbol/language, source segments, freshness, component scores,
selection reasons, and optional structural evidence. Final packets repeat the
selected reasons and scores in an optional explanation.

The default candidate pool is 50 with a 10,000 hard configuration ceiling.
Ranking combines semantic, lexical, task, working-set, recency, provenance,
freshness, and structural components. Required task state, checkpoints, and
pins are selected before value-per-token ordering. Exact source identity and
overlapping code are deduplicated.

The existing default packet fractions are 50% code, 20% structural, 15%
memory, 10% event, and 5% state. After a category-bounded pass, the current
builder performs a general fallback pass that can reclaim unused allocation in
either direction. That is unsafe for experience: a historical category could
consume the rest of a sparse packet. D074 changes the defaults to 50/20/10/5/5
plus 10% experience and makes experience reclamation one-way. Current evidence
may take unused experience budget; experience may not take another category's
unused budget.

`ContextRequest` currently has no typed active failure and no explicit
experience switch. Phase 7 must add both; a free-form query string cannot imply
authorization. Eligible ordinary experience is active, workspace-local,
verified `Success` or `PartialSuccess`, at least `Moderate`, and capped at three
items. Search may still inspect other outcomes and historical lifecycle states
explicitly.

### Storage and transaction ownership

The final v0.4.1 migration is `0006_graph_repair_generations.sql`. `SqliteStorage`
opens file databases in WAL mode with normal synchronization, a five-second
busy timeout, foreign keys enabled, and a five-connection pool. SQLx validates
and applies the immutable migration history. The supported floor is any intact
prefix beginning at `0001`; populated `0001`, `0003`, and `0004` upgrade paths
are already exercised.

Storage methods own existing multi-row transactions for memory review,
supersession, document/graph reconciliation, and repair fencing. v0.5 follows
that seam. Episode batch mutation and complete experience acceptance are single
SQLite transactions; no process mutex or adapter sequence substitutes for
database uniqueness and compare-and-swap predicates.

### CLI, MCP, workspace selection, and bounds

CLI and MCP both resolve workspaces through the facade's shared selector rules.
The MCP adapter caps frames at 1 MiB, ordinary result limits at 100, and graph
requests at 100 nodes, 500 edges, and depth 4. CLI graph requests remain within
core service ceilings. Both adapters serialize transport-neutral service
results.

MCP currently exposes session start/end and arbitrary event recording; the CLI
does not expose an equivalent episode or event lifecycle. This asymmetry does
not authorize experience policy in MCP. Phase 10 adds both adapters only after
the native episode/consolidation/search contract and integration tests pass.

### Native facade and integration evidence

`CortexWeaveService` can be constructed and exercised without CLI or MCP. It
owns workspace/session/task provenance, event and memory recording, checkpoint
operations, retrieval, context, structural queries, graph repair, and native
harness preparation/hydration. The harness contract requires active matching
session/task provenance, preserves selected source scores and source segments,
and records an auditable event for an explicit out-of-packet hydration
override.

Existing integration suites prove direct native use, shared workspace
selection, MCP stdio framing, CLI service delegation, context bounding,
structural coherence, incremental graph reconciliation, and real migration
upgrade behavior. The v0.5 facade can extend this application boundary without
a production agent harness.

## Resolved `0007` Persistence Blueprint

This is the implementation boundary, not migration code:

| Table or addition | Required identity and invariant |
|---|---|
| unique event index | `(id, workspace_id)` supports scoped evidence references without rewriting events |
| unique task/session index | `(id, workspace_id, session_id)` supports exact optional episode task ownership |
| `episodes` | unique `(id, workspace_id)`; composite session and optional task/session ownership; status/version checks; bounded normalized path/symbol JSON |
| `episode_mutation_requests` | unique workspace/episode/operation/request key; canonical request hash and resulting version |
| `episode_events` | one primary row per workspace/event; unique episode ordinal; scoped FKs; open-state and null-safe provenance triggers |
| `experiences` | scoped source episode; unique workspace input fingerprint; proposal hash; normalized signature/outcome/strength and versioned extractor/renderer identity |
| `experience_attempts` | unique stable ordinal per experience and bounded typed result |
| `experience_verifications` | one structured verifier assessment per experience with scoped event evidence when present |
| `experience_strength_bases` | ordered typed bases, rule/version, and visible reason; no naked confidence column |
| `experience_code_snapshots` | immutable path/revision/hash/logical-key/range identity independent of current rows |
| `experience_graph_snapshots` | immutable graph/analyzer/structure/node-stable-key identity layered on a code snapshot |
| `experience_evidence` | ordered bounded relation; exactly one scoped event, code snapshot, or graph snapshot target; optional attempt ownership |
| `experience_assessments` | append-only reviewed kind/reason/actor; optional cycle-checked superseding experience |
| `experience_assessment_evidence` | bounded scoped support for an assessment without mutating the accepted experience |
| `experience_fts` | derived deterministic summary/signature/path/symbol/outcome/verifier projection with doctor correspondence checks |

Episode mutation first compare-and-swaps the expected open version, then inserts
the bounded event batch and durable request result before commit. Close or
abandon is a terminal version increment. Consolidation rechecks the terminal
version and every evidence owner, then inserts or returns the complete
experience under one transaction.

The input fingerprint is BLAKE3 over a UTF-8 domain separator, one zero byte,
and the canonical v1 input. Event payloads have a separate domain-separated
hash. The proposal hash is separately domain-separated and covers every
material interpreted field. A fingerprint conflict with a matching proposal
returns the existing row; a differing proposal hash is an invariant error.
Request keys and timestamps do not affect experience identity.

## Required Decisions Closed

| Required Breakpoint 0 decision | Resolution |
|---|---|
| episodes as a distinct session-bound domain | D069; exact workspace/session/task scope |
| one primary episode per event | primary uniqueness in `episode_events`; other experiences may cite the event |
| immutable experiences and append-only assessments | D070; negative ordinary eligibility is monotonic |
| historical code snapshot identity | D071; workspace + document + logical/hash identity, never current UUID alone |
| bounded evidence relations | D072; closed enum and exactly one typed evidence target |
| structured evidence strength | D072; level + ordered bases + rule/version + reasons |
| automatic association versus causal claims | D072; temporal/structural association allowed, automatic causation forbidden |
| exact consolidation fingerprint | D073; input fingerprint plus independently checked proposal hash |
| current-source authority | D074; typed opt-in/failure gate and one-way budget reclamation |
| experience context eligibility and budget | D074; 10%, three ordinary items, verified active success/partial success at Moderate+ |
| adapter independence | D075; native/application services first, adapters parse/cap/serialize only |

## Stop-Condition Review

| Stop condition | Breakpoint 0 finding |
|---|---|
| evidence requires copying or mutating raw evidence | not triggered; references plus bounded immutable snapshots are sufficient |
| episode membership requires a production harness | not triggered; explicit facade control and session-scoped events are sufficient |
| success cannot be scoped to the failure subject | not triggered architecturally; Phase 1 must encode scope and Phase 3 must prove verifier rules |
| extractor must infer causality from time | not triggered; D072 forbids the inference |
| historical code evidence cannot survive graph reconciliation | not triggered after the D071 snapshot correction |
| ranking needs incompatible vectors | not triggered; embeddings remain outside the release blocker |
| experience displaces required current evidence | not triggered after D074's hard one-way cap; later breakpoint tests must prove it |
| schema collapses domains | not triggered; events, memories, episodes, experiences, code, and graph remain separate |

## Next Boundary

Stop here for the planned model change. Phase 1 uses GPT-5.6 Terra/high to
implement typed evidence contracts. It must begin from migration `0007` and the
D069-D075 contracts; it must not implement episodes, consolidation, experience
search/context, adapters, background workers, or model-assisted behavior early.
