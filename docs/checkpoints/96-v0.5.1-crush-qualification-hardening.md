# v0.5.1 Checkpoint 96: Crush Qualification Hardening

The emCP Crush qualification exposed three integration failures: copying a
large canonical signature was unreliable for the qualified 4B local model,
ordinary code could consume a packet before a matching Experience was selected,
and malformed nested MCP input schemas prevented the full tool list from being
converted by llama.cpp's constrained parser.

`semantic_context` now accepts `active_failure_event_id` in the transport-neutral
request. The facade resolves the stored workspace-checked Event and its failure
normalization before context assembly; callers cannot supply both the Event ID
and a signature. CLI and MCP expose the Event-ID route while retaining the
canonical-signature route for callers that already have one.

Context assembly first proves whether a matching eligible Experience was
excluded solely by ordinary packet exhaustion. If so, it measures the bounded
historical selection, rebuilds ordinary context with that exact reservation,
then appends the Experience. Current Event/member deduplication and required
task/state authority remain intact.

MCP workspace deregistration and evidence-capabilities definitions now pass
property maps to the shared schema builder rather than nesting complete schemas
inside `inputSchema.properties`. The tool-list regression asserts that those
definitions have normal object schemas.

Targeted tests prove stored-Event resolution, Experience reservation under
ordinary code pressure, and valid full-list schemas. A new sealed executable and
fresh assisted Crush smoke run remain required before release qualification can
claim Experience exposure.

The PiHype qualification then showed that asking the qualified 4B model to
reconstruct a complete captured JSON bundle was not reliable. MCP now also
offers `test_evidence_record_file`: it accepts only a workspace-relative JSON
path, canonicalizes both root and target, rejects escapes and non-files, caps
the read, parses the bundle, and delegates to the same native record service.
This is a narrow adapter-side transport aid, not a core filesystem contract or
an arbitrary-file reader.

MCP evidence record and inspection responses now project Event identity,
eligibility, decoding status, and failure normalization without echoing the raw
capture payload. The complete bundle remains durably recorded and available to
native/CLI inspection. This keeps a successful capture response bounded for
small local agent contexts without changing evidence validation or storage.
