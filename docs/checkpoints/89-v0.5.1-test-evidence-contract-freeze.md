# v0.5.1 Checkpoint 89: Test Evidence Contract Freeze

**Date:** 2026-09-04

**Breakpoint:** BP0

## Result

The Vitest and Python `unittest` boundaries have been reproduced against the
actual emCP and PiHype environments. The normalized v1 contract, exact
qualified profiles, conservative eligibility rules, receipt identity, and
adapter schemas are frozen for implementation.

Reporter and `TestResult` callbacks do not prove that a worker process exited.
Each producer must combine structured framework observations with an
independently observed process completion and exit code before writing a
completed bundle.

## Observed framework facts

Vitest 4.1.10 supplies `onTestRunEnd(testModules, unhandledErrors, reason)`.
Reported modules expose relative ID, state, errors, and complete case traversal.
Cases expose ordered suite parents, leaf name, mode, result, error classes, and
retry/repeat/flaky diagnostics. The probe preserved an ordinary pass, assertion
failure, execution error, separate skip and todo modes, a passing retry with its
earlier error, and a repeated pass.

The real emCP scope `tests/unit/hybrid-retrieval.test.ts` completed seven of
seven cases with no module or unhandled errors. Its ordinary config reported
run mode, no watch, `allowOnly: true`, snapshot mode `new`, and enabled Vitest
cache. The producer must explicitly disable snapshot writes and detect actual
focused cases. `allowOnly` and transformation/specification cache settings do
not by themselves mean the current test result was partial or replayed.

Python 3.14.7 `unittest.TestResult` supplied all required callbacks:
`startTest`, `stopTest`, success, assertion failure, execution error, skip,
expected failure, unexpected success, and subtest. `testsRun` counts parents;
subtest callbacks are separate child observations. A failed subtest did not
produce an ordinary successful parent result, so the producer must finalize the
parent from both parent and child callbacks without counting a child as a
parent.

PiHype's positive qualification is the complete class
`tests.test_core.StagnationTests`: eight cases passed, with no skip, error, or
subtest, using `.venv/Scripts/python.exe -m unittest -v
tests.test_core.StagnationTests`. `RunContractTests` and
`VerdictParsingTests` provide real subtest negative controls. A deterministic
future failure fixture changes the empty-input branch of
`backend/review.py::is_stagnant` in an isolated copy, then verifies and restores
the same complete class.

Sanitized observations are stored in
`tests/fixtures/test_evidence/vitest-4.1.10-observations.json` and
`tests/fixtures/test_evidence/unittest-python-3.14.7-observations.json`. Sealed
raw reports remain under ignored local experiment storage.

## Frozen normalized payload

`cortexweave.test_run_result` v1 has these top-level groups:

- exact producer, runner, runtime, and profile IDs and versions;
- run ID, operation, completion, optional observed exit, optional language, and
  environment fingerprint;
- project/import roots, normalized test file, file/module/class selection,
  settings digest, and inventory-complete flag;
- parent cases with ordered namespace, leaf name, distinct status, error class,
  retry configuration/count, repeat configuration/count, and flaky marker;
- child observations with parent identity, producer-local ordinal, bounded
  description, status, and error class;
- reported parent and child counts, recomputed with checked arithmetic;
- phase-qualified run errors and effective partial/watch/bail/snapshot/origin
  settings;
- typed test/configuration/dependency inputs with present before/after BLAKE3
  digests or explicit absence; and
- bounded artifact kind, digest, and reference records.

Parent states are `passed`, `assertion_failed`, `errored`, `skipped`, `todo`,
`pending`, `expected_failed`, and `unexpected_successful`. Child observations
use the same factual vocabulary but never acquire stable failure identity in
the initial profiles. A child ordinal distinguishes observations only within
one capture.

Case identity is the tuple of profile, runner, project/import roots, normalized
test file, selection kind/value, ordered namespace strings, and leaf name.
Arrays and the existing length-delimited failure encoding avoid delimiter
ambiguity. Timestamps, durations, stacks, messages, UUIDs, process IDs,
callback order, and line numbers are excluded.

## Eligibility and identity

Automatic v1 interpretation admits only a complete, current, nonempty run with
an exact registered profile, complete inventory, unchanged selected test-file
fingerprint, no run errors, no child observations, and no partial-selection or
snapshot-writing mode. All cases must pass with exit zero, or exactly one
parent must have an assertion failure with a nonzero exit. Multiple failures,
execution errors, skips, todo/pending cases, expected failures, unexpected
successes, retries, repeats, cached/replayed results, and input drift remain
decoded and inspectable but ineligible.

The failure normalizer uses the runner-qualified case tuple and error class. It
is compatible-only because one case can fail at different assertions. Vitest
and unittest cases with the same display name cannot match. Failure scope takes
language from the normalized observation; Rust remains explicit on existing
Rust compiler, Cargo test, and `cargo.check` paths.

## Receipt and transport freeze

The capture receipt key is `(workspace_id, producer_id, producer_version,
run_id)`. Its canonical request binds the normalized payload, session, optional
task, and request key. An identical retry returns the original Event; changed
content, owner, or request key conflicts. A fresh generic native-delivery key
cannot make the same captured run independent evidence.

The application operations are:

- `test_evidence_record(workspace, session_id, task_id?, request_key, bundle)`;
- `event_evidence_inspect(workspace, event_id)`; and
- `evidence_capabilities()`.

CLI maps these to `evidence record-test`, `evidence inspect`, and `evidence
capabilities`; MCP uses `test_evidence_record`, `event_evidence_inspect`, and
`evidence_capabilities`. Adapters supply bounded data and call the same native
services.

## Limits

The normalized payload limit remains 64 KiB. Additional limits are 256 parent
cases, 256 child observations, 16 namespace components, 64 run errors, 32
verification inputs, and 16 artifact references. Identifiers remain 256 bytes,
bounded text remains 4 KiB, and canonical failure components remain 512 bytes.
The first reached limit rejects the evidence; no passing subset is inferred.
