# Checkpoint 41: v0.3 Native Harness Contract

## Completed

- Added typed direct requests for active-scope context preparation and exact
  source hydration without MCP types.
- Prepared harness context always includes packet explanation and explicit
  workspace/path/symbol/score provenance for selected sources.
- Sufficiency policy is caller-owned through `HarnessContextPolicy`.
- Packet-selected chunks can be hydrated directly; out-of-packet chunks require
  an explicit reason and otherwise fail before returning source.
- Accepted overrides record a durable factual event with scope, reason, source
  provenance, and explicit unscored status.

## Full-Cycle Acceptance

The direct integration test resolves a workspace, session, and task; requests a
bounded explained packet; evaluates it through harness policy; hydrates selected
source; rejects an unauthorized source; records and returns an authorized
override; records tool/compiler/test events; activates useful evidence; records
an explicit decision; and creates a checkpoint.

## Boundary

CortexWeave neither chooses tools nor decides whether context is sufficient.
The harness owns those choices and any override authorization. MCP remains an
advisory adapter and is not part of the native policy contract.
