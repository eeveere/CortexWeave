# v0.5.1 Checkpoint 92: Test-Evidence Ingress

**Date:** 2026-09-04

**Breakpoint:** BP3

## Result

Normalized test runs now enter through a capture-specific SQLite transaction.
The receipt key is the exact `(workspace, producer, producer version, run ID)`
identity and is bound to the complete canonical request, including its owner
and bundle. An identical retry returns the original immutable Event; a changed
request key, run, provenance, or bundle conflicts instead of producing another
Event. Generic Event ingress and native delivery reject this contract.

`record_test_evidence` returns the stored Event, replay state, eligibility, and
failure normalization. `inspect_event_evidence` reloads a workspace-scoped
stored Event before decoding it. `evidence_capabilities` reports the two
qualified profiles, exact limits, separate analyzer support, and deferred
runner and aggregate-proof integrations.

The production consolidation acceptance boundary now permits only one durable
Experience for one episode. Exact acceptance retries return that original
record; an extractor-version change cannot silently add a second interpretation
for an already accepted episode. The lower-level repository still supports
explicit historical interpretation records used by review/lifecycle workflows.

## Verification

Native tests prove identical replay, changed capture/provenance/key conflicts,
ordinary and native-delivery bypass rejection, two-instance concurrent import,
owner mismatch, receipt-write rollback, stored inspection, and profile
capability reporting. Both qualified runner profiles still complete the same
native consolidation cycle. SQLite migration tests cover migration 0015 and
the accepted-episode guard prevents version-driven duplication.
