# Checkpoint 55: v0.4.1 Forensic Upgrade Audit

## Result

Breakpoint 0 is complete. The controlled evidence distinguishes normal
post-migration convergence and watcher timing from two genuine non-convergent
persisted states. No repair implementation, adapter change, or v0.5 behavior was
added.

The accepted implementation boundary is:

```text
deterministic component-aware repair plan
→ serialized in-place workspace repair generation
→ per-document D055 compare-and-swap reprojection
→ unreadable structural generation while partial
→ complete projection validation
→ atomic Current promotion
```

Phase 1 begins with Terra/high.

## Controlled Fixtures

The storage suite now constructs three real migration prefixes from the bundled
SQLx history:

- a populated `0001` floor fixture that opens directly at `0005` and preserves
  every row representable at `0001`;
- a populated `0003` skipped-version fixture that applies `0004` and `0005` in
  one current-binary open;
- a populated `0004` pre-graph fixture with Rust and Python source, three
  documents, compatible chunks and embeddings, a session, task, memory, event,
  working-set entry, context pin, and checkpoint.

The `0004` fixture is generated from current deterministic analyzer,
segmentation, and embedding identities, then persisted behind the real `0004`
migration boundary. Opening it applies the unmodified `0005` migration. The
fixture repository and database are temporary copies; source is never touched to
trigger graph work.

## Persisted State Evidence

An isolated per-document reconciliation produced these snapshots:

| Snapshot | Content / graph revision | State | Analysis states | Nodes | Facts | Edges | Unresolved |
|---|---:|---|---:|---:|---:|---:|---:|
| After migration | `1 / 0` | `Stale` | 0 | 0 | 0 | 0 | 0 |
| After first unchanged document | `1 / 0` | `Stale` | 1 | 3 | 7 | 5 | 2 |
| After all three documents | `1 / 1` | `Current` | 3 | 7 | 12 | 12 | 0 |

Every analysis step produced zero embeddings. Document content revisions stayed
at 1. Document IDs, chunk IDs, stable keys, content hashes, and embedding rows
survived. Session, task, memory, event, working-set, pin, and checkpoint rows
also survived unchanged.

The intermediate snapshot proves that current-only structural reads reject the
stale graph while `allow_stale` currently returns the already-written partial
projection. That read behavior is unsafe for an in-place workspace repair and
is superseded by D065 for active or incomplete repair generations.

## Symptom Classification

### Expected migration state

`0005_graph_domain.sql` deliberately creates a `Stale` watermark at content
revision 1 for a populated pre-graph workspace and creates no graph document
states, nodes, or edges. Useful semantic retrieval alongside empty structural
evidence is therefore expected before repair; it is not evidence that legacy
chunks or embeddings were lost.

### Normal isolated convergence exists

Ordinary workspace reindex sees the missing graph analysis state, re-analyzes
all three unchanged documents, computes zero embeddings, and reaches `Current`.
Its legacy outcome reports three `files_updated`, even though source content did
not change. The path exists, but the outcome conflates graph work with source
updates and does not prove what happened.

### Watcher timing explains a later zero-work command

Watcher startup arms filesystem notifications and then synchronously calls the
same workspace reindex before returning its handle. The isolated watcher fixture
reached the same `Current` graph with zero embedding calls. A subsequent manual
reindex reported:

```text
files_seen: 3
files_updated: 0
files_failed: 0
files_removed: 0
chunks_embedded: 0
```

This reproduces the OPiHype outcome shape without a missing migration repair
path. Because the shipped outcome has no graph fields, the historical OPiHype
result alone cannot distinguish watcher-completed convergence from a skipped or
failed repair. Final graph status is the necessary discriminator.

### Compatible analysis rows can mask a missing projection

A fixture with compatible graph-document states but no nodes, facts, or edges
remained `Stale` after ordinary reindex. Every file returned `Unchanged`, so the
command reported zero updates and made no repair attempt. The current fast path
checks document analysis compatibility but not projection completeness.

Current v0.4 graph mutation writes document state and projection rows in one
transaction, so normal D055 operations do not create this mismatch. It can still
represent historical defects, external corruption, or future compatibility
mistakes and is explicitly repairable v0.4.1 input. Phase 1 must classify it as
`missing_projection` or the accepted equivalent.

### An abandoned update marker does not recover

A complete current graph changed to `Updating` with no active owner remained
`Updating` after ordinary reindex. Compatible per-document states caused every
file to skip, and no workspace-level recovery rule ran. v0.4.1 therefore needs a
durable repair generation and compare-and-swap lease takeover rather than a
startup-time unconditional reset.

### CLI selector inconsistency is confirmed

MCP resolves a workspace selector before calling the facade. The CLI reindex
path passes its positional value directly to `workspace_reindex`, whose facade
contract requires an exact ID. The displayed workspace name can therefore fail
while its UUID succeeds. This is an adapter parity defect reserved for Phase 5;
it is not part of graph repair orchestration.

### Binary/schema failure is safe but opaque

Storage still delegates migration validation to SQLx and the top-level error is
a transparent migration wrapper. An older binary therefore fails safely on a
newer or changed history, but it cannot add executable, config, database-path,
or supported-range context. The observed `Migration(VersionMissing(4))` is a
diagnostic defect, not authorization to weaken migration validation or recreate
the database.

## Accepted Atomicity and Read Decision

D065 selects serialized in-place reprojection under one durable workspace repair
generation.

- Existing D055 per-document transactions and source-snapshot checks remain.
- A new migration adds enough repair-generation and per-document projection
  metadata to distinguish active, interrupted, failed-partial, and complete
  work and to detect missing projection rows.
- Current-only reads fail throughout an active or incomplete generation.
- Explicit stale reads may read a coherent prior projection before repair begins,
  but fail from in-place generation acquisition until successful completion.
- Status and doctor remain readable; semantic and lexical retrieval continue
  without structural evidence.
- Watcher, reindex, and explicit rebuild share one lease and one service policy.
- Only the generation owner may perform final completeness validation and
  promote `Current`.

This accepts a bounded structural-read outage during `force` repair in exchange
for avoiding duplicate graph storage and preventing mixed projections from being
presented as coherent evidence.

## Known Limitations and Later Gates

- The deterministic fixture is intentionally small; OPiHype-scale copied-data
  qualification remains Breakpoint 2.
- The fixture proves watcher-first ordering and the zero-work manual result. Full
  concurrent watcher/manual, source-edit, lease-expiry, and process-restart
  attacks remain Breakpoint 1.
- Projection completeness representation is constrained by D065 but its exact
  schema belongs to Phase 1.
- Package-version alignment is planned, not implemented in this breakpoint.
