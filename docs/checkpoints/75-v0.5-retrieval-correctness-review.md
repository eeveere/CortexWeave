# v0.5 Checkpoint 75: Retrieval Correctness Review

**Date:** 2026-08-30

**Scope:** Breakpoint 7 adversarial review on GPT-5.6 Sol/high

## Result

The Phase 6 implementation required correction before the retrieval gate could
pass. The review found that a query-only request merged the recent-candidate
source and could therefore return unrelated Experiences. It also found that
the merged ID set was lexicographically truncated before records were scored,
which could discard an exact-signature candidate behind 200 lexical IDs.

Recent candidates are now included only when no signature, component, lexical,
path, or graph selector exists. The complete union of individually bounded
candidate queries is hydrated and scored; it is never truncated by identifier
order. Exact signature still receives more score than the maximum combination
of all weaker signals. Empty or operator-only lexical input and mutated
noncanonical FailureSignature values are rejected at the service boundary.

## Historical Resolution

Document freshness and graph-symbol resolution are now independent facts.
Every historical code snapshot reports `current`, `content_changed`, or
`deleted` document status. Every associated graph snapshot separately reports
`current`, `missing`, or `unavailable`; a code snapshot without graph capture
reports `not_captured`. Multiple graph snapshots associated with one code
snapshot are all explained rather than silently reducing to the first.

Graph keys resolve only against a graph revision proven current. A matching
stable key after a body edit therefore remains visible as current while the
document reports changed content. A removed or renamed historical symbol is
reported missing, and a stale graph is reported unavailable. Historical path,
hash, revision, and stable key remain unchanged in every result.

## Adversarial Outcomes

| Comparison | Result |
|---|---|
| exact same failure and scope | exact score; outranks all weaker results |
| same diagnostic, different symbol | compatible component result, not exact |
| similar summary, different failure | lexical/component result below exact |
| same path, stale symbol | path remains historical; graph status is missing |
| exact symbol key after body edit | document changed; graph key current |
| deleted/renamed historical symbol | deleted or missing is explicit; no rewrite |
| successful versus inconclusive | exact outcome filters isolate each state |
| active versus disputed | active is default; disputed requires explicit filter |
| identical other workspace | only the explicitly requested workspace returns |

Additional regression coverage proves an exact ID survives a union containing
200 lexicographically earlier lexical IDs and that query-only misses return no
recent fallback records. The complete project quality gate passes.

Phase 7 remains unstarted.
