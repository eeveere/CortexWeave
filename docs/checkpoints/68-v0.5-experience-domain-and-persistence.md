# v0.5 Checkpoint 68: Experience Domain and Persistence

## Scope

Implemented the Phase 4 historical Experience domain and its additive SQLite
schema. This phase provides durable aggregate persistence only; it does not
yet extract or consolidate experiences from episodes.

## Delivered

- Immutable `Experience` records with outcome, verification, strength bases,
  renderer version, extractor identity, exact fingerprint, and proposal hash.
- Ordered attempt and event-evidence relations, immutable code/graph snapshots,
  and append-only assessments with bounded supporting evidence.
- Deterministic, causal-humble summary renderer. Persistence rejects a summary
  that does not exactly match the current renderer output.
- SQLite migration `0008`, composite workspace foreign keys, immutable-row
  triggers, exact fingerprint uniqueness, and an `experience_fts` projection.
- An internal aggregate persistence primitive for the future consolidator,
  plus native façade methods to get records and append/read reviewed
  assessments. Arbitrary caller-constructed Experiences cannot be accepted.

## Storage Proofs

The repository proof covers:

- foreign-workspace event evidence rejected by SQLite;
- ordered attempts and evidence round-trip exactly;
- a failed child insertion rolls back the whole aggregate;
- code snapshot content survives deletion of its current chunk;
- immutable experience and assessment updates fail;
- FTS receives one row for a persisted experience;
- exact fingerprint/proposal repeats return the existing record, while a
  different proposal hash conflicts;
- upgrading prior data creates no fabricated experiences.

## Boundary

No consolidation algorithm, search ranking, context selection, CLI, MCP
adapter, embedding, or automatic dispute/supersession logic was introduced.
