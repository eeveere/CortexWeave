# v0.2 Final Adversarial Review

## Classification

### Fixed v0.2 Blockers

1. **Superseded memory can re-enter semantic context through direct FTS.**
   Temporal retrieval excludes superseded memory by default, but direct memory
   candidates use `search_memories` and hydrate the superseded record. A strong
   lexical match can therefore select stale content despite its zero freshness
   score. Direct candidates now omit superseded memory after hydration.
2. **Explicit task/session context can admit unrelated state candidates.**
   Candidate-pool temporal retrieval is workspace-wide. Explicit task and
   session state are boosted, but other task/session rows remain eligible and
   can consume packet budget. `task_state` and `session_state` are now scoped to
   the effective explicit scope. Workspace-wide durable memory remains
   intentional.

### Fixed Hardening

1. **Configured candidate growth needs an upper bound.** Candidate and per-seed
   structural limits are positive but currently unbounded. Defaults are small
   and runtime queries are bounded by the configured values, yet pathological
   configuration can cause avoidable query and expansion cost. Validated ceilings
   of 10,000 candidates and 64 structural expansions preserve the defaults.
2. **Explicit supersession should reject cycles.** Foreign keys enforce
   workspace identity and self-supersession is forbidden, but a longer cycle is
   representable through direct storage calls. A transactional recursive query
   now rejects insertion when the newer memory already reaches the older memory
   through the supersession chain.

### v0.3

v0.3 adds workspace analyzer-readiness reporting, implementation-coverage
context evaluation, and a direct native-harness control contract before the
deferred memory-integrity work: provenance/trust policy, overlap-aware duplicate
token detection, and explicit memory consolidation. See the
[v0.3 plan](v0.3-plan.md).

### Rejected as Current Defects

- **Recency over-weighting:** default recency weight is 0.10, provenance and
  freshness remain independent, and temporal result order prefers current source.
- **Working-set lock-in:** activation decays, unpinned entries are pruned and
  bounded, and pins are explicit required state by design.
- **Token-budget overflow:** one shared counter, required-item truncation, total
  accounting, and torture tests enforce the total budget.
- **Cross-workspace leakage:** service validation, workspace predicates, and
  composite foreign keys preserve provenance boundaries.
- **Language-specific orchestration:** candidate, structural, ranking, resume,
  and budgeting code consume normalized analyzer output without language checks.
- **MCP coupling:** no domain, service, storage, retrieval, or indexing module
  imports adapter types.

## Hardening Gate

All four fixes have focused regression coverage. The complete formatter, check,
Clippy, and test gate remains the final verification step.
